# Documentation and Onboarding

- Onboarding documents bind to a source commit and carry evidence levels.
- Stale documentation is a `KNOWN_GAP`, never silently trusted.
- Updates go through review like code.

## Onboarding quality bar

Include source commit, language/framework versions, module map, entry points,
build/test/run commands, environment prerequisites, API schemas, data stores,
deployment/runtime, ownership, flags, dependencies, known gaps, and update
triggers. Separate generated summaries from human-confirmed facts. A targeted
sync preserves unchanged evidence and updates only affected claims.
