# General

- All work is evidence-led; every claim carries a source and an evidence level.
- Fictitious data only in public repos; internal values belong to `TODO(INTERNAL)` entries.
- One self-contained change per commit; the commit message references the ticket.
- Stop at human gates; never approve, merge, or publish on behalf of a person.

## Operating checklist

- Start by stating task, repository, Journey/workflow ID, current commit, and
  intended output.
- Use the smallest tool scope that can answer the question; inspect before
  editing.
- Separate facts, decisions, assumptions, unknowns, and recommendations.
- Every changed file has a reason and every completed claim has executable
  evidence.
- Stop at a human decision instead of converting a plausible guess into a
  rule.
